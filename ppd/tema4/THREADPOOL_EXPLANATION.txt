================================================================================
The Critical Part: How Do Threads Get Different Tasks?
================================================================================

Here's the **key mechanism** that ensures different threads get different tasks:

{
    unique_lock<mutex> lock(queue_mutex);     // ← ONLY ONE thread can be here

    cv.wait(lock, [this]{ return !tasks.empty() || stop; });

    if (stop && tasks.empty())
        return;

    task = tasks.front();   // ← Get FIRST task
    tasks.pop();            // ← REMOVE it from queue immediately!
}  // ← Unlock

**The magic is: `tasks.pop()` removes the task BEFORE releasing the lock!**

**Each thread gets a DIFFERENT task because:**
1. Only one thread can hold the lock at a time
2. That thread takes the front task
3. That thread **removes** it from the queue (pop)
4. Next thread sees a different front task

Why the Curly Braces Matter
================================================================================

{
    lock(queue_mutex);
    task = tasks.front();
    tasks.pop();
}  // ← UNLOCK HERE

task();  // ← Execute WITHOUT lock (parallel execution!)

**If there were no braces:**

lock(queue_mutex);
task = tasks.front();
tasks.pop();
task();              // ← Execute WITH lock held!
// Unlock at end of while iteration

**Problem:** Thread holds lock during execution, blocking all other threads.

================================================================================
Summary
================================================================================

**Your questions answered:**

1. **"Don't they all continue in the curly braced area?"**
   - No! Only ONE at a time can be in the locked section (lines 28-40)
   - The mutex ensures only one thread holds the lock

2. **"How do we know threads take different tasks?"**
   - Because each thread does `tasks.pop()` while holding the lock
   - By the time next thread enters, the previous task is already removed
   - `tasks.front()` always returns the current first element

3. **"Is this why we have curly braces?"**
   - The braces ensure lock is released **before** executing the task
   - This allows multiple threads to execute tasks **in parallel**
   - Without braces: tasks execute sequentially (defeats the purpose!)

4. **"Shouldn't threads all do work simultaneously?"**
   - **YES!** And they do, **because of the curly braces**
   - Lock is only held during queue access (very fast)
   - Task execution happens outside the lock (parallel)

The combination of **mutex** (ensures different tasks) and **curly braces**
(enables parallel execution) makes the thread pool work correctly!
