  - Add: std::condition_variable cv_not_empty (for consumers)

□ Rewrite push() method:

  - Lock mutex
  - Wait on cv_not_empty while queue is empty
  - Pop item from queue

  - Return item

NOTES & TIPS
================================================================================

Thread Pool Implementation:
- Can use a simple implementation or reference existing C++ thread pool libraries
- Key: Task queue + worker threads + condition variable for notification

Condition Variables vs Semaphores:
- Condition variables more flexible
- Must use with mutex and while loop (not if!)
- Pattern: lock -> wait while(condition) -> work -> notify -> unlock

Fine-Grain Locking Strategy:
- Always lock in same order (head to tail) to avoid deadlocks
- Hand-over-hand: lock current, lock next, unlock current, move forward
- Never hold more than 2 adjacent locks at once

Debugging Tips:
- Add logging to track which thread is doing what
- Use std::cout with mutex for thread-safe printing
- Test with small data first (10 students) before scaling to 500
- Valgrind for memory leaks: valgrind --leak-check=full ./program

Performance Expectations:
- Fine-grain locking should improve parallel performance
- With 500 students, overhead amortized better than Lab 4 (200 students)
- Bounded queue prevents memory issues with large datasets
